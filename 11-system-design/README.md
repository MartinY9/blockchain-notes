# 第十一篇 区块链系统设计

> 从系统架构角度理解一条链怎么被设计出来。
> 万能框架：**分层拆解 → 逐层给方案 → 说清权衡（trade-off）**。

---

## 11.1 设计一个联盟链

**思路：自底向上分层，每层给出关键设计点。**

```
网络层  →  身份管理  →  共识层  →  执行层  →  存储层  →  应用层
```

| 层 | 关键设计点 |
|----|------------|
| **网络层** | P2P（Gossip）、节点发现、TLS 加密通信、分区/多机房容灾、节点准入 |
| **身份管理** | CA / PKI 体系、成员身份（如 Fabric 的 MSP）、角色权限（读/写/背书/排序）、证书吊销 |
| **共识层** | PBFT / HotStuff / Raft（确定性最终性）；根据节点数和容错需求选型；主节点选举与视图切换 |
| **执行层** | 智能合约引擎（EVM / WASM / 链码）、交易校验、并行执行、Gas/资源计量（联盟链常做资源配额而非收费） |
| **存储层** | 区块存储（追加）、状态存储（RocksDB/LSM）、Merkle 结构做完整性证明、历史归档 |
| **应用层** | BaaS 平台、SDK/API、浏览器、监控、跨链网关、隐私保护（ZK/TEE/同态） |

**容易忽略但重要的横切能力**：**隐私保护**（数据分区/通道、零知识、可信执行环境 TEE）、**合规审计**（KYC、可审计日志）、**可运维性**（监控、升级、灰度）、**跨链网关**。

> 设计思路：先确定**信任假设**（谁参与、容忍多少作恶节点 f），它决定共识选型（3f+1）；再确定**性能目标**（TPS、最终性延迟），它决定并行/存储方案。**从需求推导设计**，而不是罗列组件。

---

## 11.2 为什么区块链慢 + 如何提升 TPS

**先理解「为什么慢」**：区块链慢是因为**每个节点都要重复执行并存储所有交易，还要跨网络达成共识**——用「全局冗余」换「无需信任」。所以优化就是围绕「共识 / 执行 / 存储 / 网络」四个瓶颈：

| 瓶颈 | 优化方向 | 具体手段 |
|------|----------|----------|
| **共识** | 减少通信复杂度、加快最终性 | PBFT → HotStuff（O(n²)→O(n)）、流水线、聚合签名（BLS）、Narwhal（Mempool 与共识分离） |
| **执行** | 并行化 | 并行交易执行（Block-STM、Sealevel、对象级并行）、预声明读写集、乐观执行 |
| **存储** | 减少 I/O、防状态膨胀 | 状态缓存、状态分片、批量写、状态过期、Verkle Tree |
| **网络** | 加快传播 | 批量/紧凑区块传播、Gossip 优化、更好的拓扑 |
| **分层** | 把负载移出主链 | Layer2 / Rollup、状态通道、侧链 |
| **分片** | 水平扩展 | Sharding（把交易/状态分到多个分片并行处理） |

> 关键权衡：**提升 TPS 往往牺牲去中心化**（如提高硬件门槛、减少节点数），要在不可能三角里取舍。别只说「上并行/分片」，也要说代价。

## 11.3 如何保证稳定性 / 高可用？

区块链系统也是分布式后端系统，稳定性设计与传统高可用相通：

- **多副本 / 冗余**：节点多机房、多地域部署，无单点。
- **容灾**：主备切换、共识层的视图切换（换主）、故障节点自动隔离与恢复。
- **监控告警**：节点健康、出块延迟、交易积压、分叉检测、资源水位。
- **限流**：交易入口限流、mempool 上限、防 DoS（联盟链可做准入 + 配额）。
- **降级**：非核心功能降级（如暂停复杂查询、只读模式），保出块与核心交易。
- **灰度与可升级**：合约/节点可升级（代理模式），灰度发布，回滚预案。
- **数据一致性与备份**：定期快照、区块归档、状态可重建。

> 理解方式：把它当成**「区块链 + 传统 SRE」** 的结合——既有区块链特有的（分叉、共识活性、最终性），又有通用的（多副本、监控、限流、降级）。

## 11.4 其他常见系统设计场景

- **设计一个跨链桥**：信任模型选择（轻客户端 vs 多签）、消息验证、重放保护、限额/熔断（防被盗后损失扩大）、监控异常提款。
- **设计一个高性能 DEX / 撮合**：链上 AMM vs 链下订单簿 + 链上结算；MEV 防护。
- **设计一个 NFT/RWA 发行平台**：铸造、元数据存储（IPFS）、合规校验（KYC 白名单 / ERC-3643）、二级市场、预言机喂价。
- **设计钱包 / 账户系统**：私钥管理、账户抽象（AA）、多签、社交恢复、Agent 消费限额（呼应第九篇 x402）。

---

## 本篇小结

- 设计一条链就是分层设计，从信任假设和性能目标反推每层选型，别忘隐私/合规/运维等横切能力。
- 区块链慢的本质是「全局冗余换无需信任」；提 TPS 从共识/执行/存储/网络四瓶颈 + 分层 + 分片入手，代价是去中心化。
- 稳定性 = 区块链特性（分叉/最终性/活性）+ 传统 SRE（多副本/监控/限流/降级）。
