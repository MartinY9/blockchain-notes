# 第一篇 区块链基础与技术演进史

> 这一篇的重点不是记时间线，而是理解**每一代技术在解决上一代的什么瓶颈**。
> 把整个区块链史串成一条「不断在不可能三角上做取舍」的演进逻辑。

---

## 1.1 一条主线看懂区块链演进

```
密码朋克思想  →  Bitcoin（价值转移）  →  Ethereum（可编程金融）
      →  联盟链（企业级/合规）  →  Web3 与模块化区块链（可扩展性）
```

每一步都是在回答一个新问题：

| 阶段 | 要解决的核心问题 |
|------|------------------|
| 密码朋克 | 没有中心机构，如何保护个人隐私与数字身份？ |
| Bitcoin | 没有可信第三方，如何完成价值转移（解决双花）？ |
| Ethereum | 除了转账，能否在链上运行任意逻辑（可编程）？ |
| 联盟链 | 企业场景下如何兼顾性能、权限、合规？ |
| Web3/模块化 | 在保证安全去中心化的前提下，如何扩容？ |

---

## 1.2 密码朋克运动与去中心化思想

**Cypherpunk（密码朋克）** 是 1980s–1990s 的技术社群，核心信条是「用密码学而非法律来保护个人隐私」。比特币白皮书正是中本聪在密码朋克邮件列表里发布的。所以区块链的**思想根源在密码学与隐私，而不是金融**。

理解区块链，先掌握四块密码学基石：

- **公钥密码体系（非对称加密）**：一对密钥——公钥可公开、私钥须保密。区块链里「地址 ≈ 公钥的哈希」，「拥有资产 = 拥有私钥」。
- **Hash 函数**（如 SHA-256）：
  - 特性：确定性、抗碰撞、雪崩效应（输入变一点输出全变）、单向不可逆。
  - 用途：区块链接（每个区块存前一个区块的哈希）、Merkle Tree、PoW 难题、地址生成。
- **数字签名**：用私钥签名、公钥验签。保证交易**不可伪造 + 不可抵赖**。链上没人知道你是谁，但能验证「这笔交易确实由某私钥持有者授权」。

### 理解：为什么比特币能解决双花问题？

**双花（Double Spend）** 就是同一笔钱被花两次。数字信息可以无限复制，所以在没有中心账本（银行）时，双花是数字货币最难的问题。

比特币的解法是**「用去中心化的全局账本 + 经济博弈，达成对『交易顺序』的共识」**，可以分三层理解：

1. **每笔花费都要引用来源（UTXO）并附数字签名**：这防止伪造，但还不能防止「同一个 UTXO 同时发给两个人」。
2. **全网维护一个唯一的、按时间排序的账本（区块链）**：双花的两笔交易不可能同时被合法确认——只有一条链会被承认。
3. **PoW + 最长链规则决定「哪条链是真的」**：攻击者要让双花成功，必须比全网算力更快地重构区块，即掌握 **51% 算力**，成本极高。

所以比特币不是「数学上不可能双花」，而是**「作恶成本 > 收益」**。

> 深入一点：比特币解决的是**拜占庭环境下的最终一致性**，而且是**概率最终性**——确认（confirmation）越多越安全，6 个确认约 1 小时。这与后来 BFT 类共识的「确定性最终性」有本质区别（见第三篇）。

## 1.3 Bitcoin 时代（2008–2014）

**Bitcoin 解决的问题一句话：在没有可信第三方的情况下，实现价值转移。**

核心技术：

- **UTXO 模型（Unspent Transaction Output，未花费交易输出）**：账本不是「账户余额」，而是一堆「未花费的输出」。转账 = 消费若干 UTXO、生成新的 UTXO。钱包把你能解锁的 UTXO 加总，就是你的「余额」。
  - 优点：**天然可并行验证**（不同 UTXO 互不依赖）、无全局状态、隐私性更好、无重放问题。
  - 缺点：不适合表达复杂状态（比如「一个合约的内部变量」）。
- **PoW 共识（Proof of Work）**：矿工比拼算力求解 Hash 难题（找到使区块哈希小于目标值的 nonce）。
- **Merkle Tree**：把区块内所有交易哈希两两向上聚合成一个 **Merkle Root** 放进区块头。作用：轻节点可用 **Merkle Proof** 验证「某交易是否在区块中」而无需下载全部交易（SPV，简单支付验证）。
- **P2P 网络**：无中心服务器，节点对等，交易/区块通过 Gossip 扩散。
- **区块链账本**：区块按时间用哈希首尾相连，改动任一历史区块都会导致后续所有哈希失效 → **不可篡改**。

## 1.4 Ethereum 时代（2015– ）

**从「数字货币」发展到「可编程金融」。** 打个比方：Bitcoin 是一台计算器（只会转账），Ethereum 是一台世界计算机（能跑任意程序）。

核心：

- **Account 账户模型**：直接维护「地址 → 余额/状态」的全局状态（world state）。分外部账户（EOA，私钥控制）和合约账户（代码控制）。
- **Smart Contract 智能合约**：部署在链上的代码，满足条件自动执行，不可篡改。
- **EVM（Ethereum Virtual Machine）**：栈式虚拟机，所有节点执行相同字节码得到相同结果（确定性）。
- **Gas 机制**：每个操作消耗 Gas，用户付费。防止无限循环、为资源定价。

### 理解：以太坊为什么用账户模型而不是 UTXO？

关键在于**以太坊要支持有状态的智能合约**：

1. **合约需要持久化的内部状态**（比如一个 ERC-20 合约要记录所有人的余额映射）。UTXO 是无状态的碎片，表达「全局可变状态」非常别扭；账户模型天然就是 key-value 状态存储，合约读写状态直观。
2. **开发者心智更简单**：账户模型接近传统编程里的「变量」概念，写合约更自然。
3. **交易更紧凑**：账户模型下转账只需 from/to/value，不必像 UTXO 那样选择并引用一堆输入。

代价（体现权衡）：

- 账户模型有**全局状态竞争**，难以并行执行（两笔交易可能都改同一个账户）；UTXO 天然易并行。
- 账户模型需要 **nonce** 来防重放（UTXO 天然防重放，因为输出只能花一次）。

> 一句话总结：**UTXO 为「安全 + 并行」优化，Account 为「表达力 + 可编程」优化。** 不同状态模型服务不同目标，这就是演进逻辑。

## 1.5 联盟链时代（2016– ）

代表：**Hyperledger Fabric、FISCO BCOS、蚂蚁链（AntChain）、R3 Corda**。

出现原因：公链虽然去中心化，但**企业需要权限控制、高 TPS、合规、隐私**——匿名开放的公链无法直接满足监管和商业需求。

### 公链 vs 联盟链

| 维度 | 公链 | 联盟链 |
|------|------|--------|
| 参与方式 | 开放参与（Permissionless） | 许可参与（Permissioned） |
| 共识 | PoW / PoS | PBFT / Raft / HotStuff |
| 身份 | 匿名 | 实名（有 CA/MSP 身份体系） |
| 典型场景 | 金融开放、公开资产 | 产业应用、供应链、政务 |
| 性能 | 低 TPS（几十~几千） | 高 TPS（数千~数万） |
| 信任模型 | 无需信任任何人 | 参与方部分互信 |

> 理解：联盟链其实是**「用牺牲开放性/去中心化，换性能与合规」**——同样落在不可能三角上。它不是「更落后的区块链」，而是**为不同信任假设做的工程选择**。

## 1.6 Web3 与模块化区块链时代（2020– ）

关键词：**Layer2、Rollup、Modular Blockchain（模块化区块链）、ZK（零知识证明）**。

核心矛盾：以太坊要保持去中心化和安全，就无法在 L1 直接大幅扩容（区块大小、Gas 上限有限）。解法是**分层与模块化**：

- **单体链（Monolithic）**：一条链自己搞定执行、共识、结算、数据可用性（如早期以太坊、Solana）。
- **模块化链（Modular）**：把这几层拆开、各司其职：
  - **执行层**：Rollup（Optimism、Arbitrum、zkSync）
  - **结算层 + 共识层**：以太坊 L1
  - **数据可用性层（DA）**：Celestia、EigenDA

代表事件：**Ethereum 2.0 / The Merge（2022，PoW → PoS）**，以及以 Rollup 为中心的路线图（Rollup-centric roadmap）。

> 演进逻辑一句话：**Bitcoin 做「价值」，Ethereum 做「可编程」，联盟链做「合规落地」，模块化做「可扩展」。** 每一代都在不可能三角上换一个角度突破。

---

## 本篇小结

- 区块链的思想根在密码学（公钥、Hash、数字签名），不在金融。
- 比特币靠「全局排序账本 + PoW + 最长链」解决双花，本质是「作恶不划算」+ 概率最终性。
- UTXO（安全/并行）与 Account（可编程）是两种目标不同的状态模型；以太坊为了智能合约选了 Account。
- 公链与联盟链的差异根源是**信任假设不同**，进而决定了共识、身份、性能的不同。
- 整条演进线可以用不可能三角来串：每一代都在「去中心化 / 安全 / 性能」上换角度突破。
