# 第三篇 共识算法演进

> 共识是区块链的心脏。这一篇按演进顺序理解：**为什么需要共识 → PoW → PoS → BFT → DAG → 新一代高性能共识**，
> 每一步都在优化「安全 / 去中心化 / 性能」中的某个角。

---

## 3.1 为什么需要共识？

分布式系统的根本问题：**多个节点，如何对「唯一的结果 / 顺序」达成一致？**

区块链的难点在于运行在**拜占庭环境**（节点可能作恶、说谎、掉线）。共识要同时保证：

- **一致性（Safety）**：诚实节点不会认可两个冲突的结果（不双花）。
- **活性（Liveness）**：系统持续出块、交易最终被处理。

一个重要理论结论 **FLP 不可能定理**：异步网络中，只要有一个节点可能故障，就不存在既保证安全又保证活性的确定性共识。所以现实共识都做了取舍（引入同步假设、随机性、或牺牲部分活性）。

**两类最终性：**

- **概率最终性**（PoW、PoS）：确认越多越安全，但理论上永远可被更长链推翻。
- **确定性最终性**（PBFT、HotStuff、Tendermint）：区块一旦提交即不可逆。

---

## 3.2 PoW（Proof of Work，工作量证明）

代表：**Bitcoin、（早期）Ethereum**。

**原理**：矿工不断改变 nonce 计算区块哈希，直到哈希小于目标难度值（**Hash Puzzle**）。谁先算出谁出块，全网以**最长（最重）链**为准。

- **优点**：极高的安全性与去中心化（作恶需 51% 算力，成本巨大）；无需身份、开放参与。
- **缺点**：**能耗巨大**、**TPS 低**（比特币约 7 TPS）、确认慢（概率最终性）、算力向矿池集中。

### 理解：PoW 为什么安全？

因为**攻击成本 = 持续掌握全网 51% 以上算力**。这需要天量的硬件和电力投入，而且一旦攻击成功导致币价崩盘，攻击者自己的巨额投入也归零——**经济激励让「诚实挖矿」成为理性选择**。安全性来自「作恶不划算」，而非数学上不可能。

---

## 3.3 PoS（Proof of Stake，权益证明）

代表：**Ethereum（The Merge 后）、Cardano、Polkadot**。

**思想转变**：从「计算资源竞争」→「资本质押」。验证者质押代币获得出块权，作恶会被没收质押（Slashing）。

- **优点**：能耗极低、资本效率高、更易实现快速最终性（配合 BFT 类 finality gadget）。
- **经典问题 —— Nothing at Stake（无利害关系）**：分叉时，验证者「在每条分叉上都投票」没有额外成本，反而可能两边下注，导致链无法收敛。
  - **解法：Slashing（罚没）**。对「双签 / 在冲突区块上投票」的验证者没收质押，让作恶有真实代价。
- **其他风险**：长程攻击（Long-range Attack，用旧私钥重写历史）→ 用弱主观性检查点缓解；以及「富者愈富」的中心化担忧。

### 理解：PoS 如何抵御攻击？

核心是**把「链上身份」和「真实经济代价」绑定**：想出块要质押，作恶（双签、支持冲突链）会被 Slashing 没收本金甚至驱逐。于是 Nothing-at-Stake 从「零成本」变成「高成本」，理性验证者只会诚实出块。以太坊还叠加了 Casper FFG 的**最终性 gadget**，两轮投票（justify + finalize）后区块不可逆。

---

## 3.4 BFT 共识（拜占庭容错）

代表：**联盟链常用 —— PBFT、Tendermint、HotStuff**。适合已知验证者集合（许可环境）。

### PBFT（Practical Byzantine Fault Tolerance）

- **容错上限 3f+1**：要容忍 f 个拜占庭节点，至少需要 **3f+1** 个节点。原因：需要有 **2f+1** 个诚实节点的多数，才能在「f 个作恶 + f 个可能不响应」的情况下仍形成不可伪造的多数决。
- **三阶段**：`Pre-prepare → Prepare → Commit`。
  - Pre-prepare：主节点广播提案。
  - Prepare：各副本互相广播，收集到 2f+1 个 Prepare 表示「对该提案达成局部一致」。
  - Commit：再收集 2f+1 个 Commit，即可提交（确定性最终性）。
- **优点**：确定性最终性、秒级确认、高 TPS。
- **缺点**：**通信复杂度 O(n²)**（每阶段节点两两广播），节点一多就爆炸，所以只适合几十~一两百个节点的联盟链；视图切换（换主）复杂。

### HotStuff（Facebook Libra/Diem 提出）

在 PBFT 基础上的关键改进：

- **线性通信复杂度 O(n)**：引入 **leader 收集签名并聚合（门限/BLS 聚合签名）**，节点只跟 leader 通信，不再两两广播。
- **流水线（pipelining）**：每个区块的多阶段投票可以流水线并行，吞吐更高。
- 因此更适合**大规模验证者集**，成为很多现代 PoS 链（Aptos、部分 L1）的共识基础。

### Tendermint（Cosmos）

PBFT 思想 + PoS，即时最终性，是 Cosmos 生态和很多应用链的共识引擎。

### 理解：PBFT 为什么 3f+1？HotStuff 好在哪？

- **3f+1**：为在最坏情况（f 作恶 + f 掉线）下仍能拿到诚实多数（quorum 需 2f+1）。两个 quorum 必有交集，且交集必含诚实节点，从而保证不会产生冲突提交。
- **HotStuff 优势**：把 PBFT 的 **O(n²) 通信降到 O(n)**（leader 聚合签名），并通过流水线提高吞吐、简化视图切换——让 BFT 能扩展到成百上千验证者。

## 3.5 DAG 共识

代表：**Hashgraph、Avalanche、Fantom、（Mempool 层）Narwhal**。

**思想**：不再是单条线性链，而是**有向无环图**——区块/交易可以并行地引用多个父节点。

```
        Block1
       /      \
   Block2    Block3
       \      /
        Block4
```

- **优点**：天然**高吞吐**（多个出块者可并行产块，不必争抢单一链头）、无「孤块浪费」。
- **难点**：如何从 DAG 中确定一个**全局线性顺序**（total order）来防双花——这是各 DAG 方案的核心差异。

## 3.6 新一代高性能共识

### Solana：PoH + Tower BFT

- **PoH（Proof of History）**：一条基于哈希的连续链，为事件打上**可验证的时间顺序戳**。它本身不是共识，而是**「预先排好序的时钟」**，让验证者不必来回通信就对「谁先谁后」达成一致。
- **Tower BFT**：建立在 PoH 之上的 PBFT 变体，用 PoH 作为全局时钟简化投票。
- 效果：极高 TPS，但对节点硬件要求高、去中心化程度相对较低（再次落回不可能三角）。

### Avalanche Consensus（随机采样 / 亚稳态共识）

- 每个节点**反复随机抽样**一小撮其他节点问「你选哪个」，根据多数回复调整自己的偏好，多轮后全网快速收敛（亚稳态 metastability）。
- 优点：可扩展到海量节点、低延迟、概率安全性可调；与传统「全体投票」的 BFT 路线完全不同。

### Narwhal + Bullshark（Mempool 与共识分离）

- **核心思想：把「数据传播/排序（Mempool）」和「达成共识（consensus）」解耦。**
  - **Narwhal**：一个基于 DAG 的高吞吐 Mempool，负责可靠地传播交易并形成 DAG 结构（保证数据可用性）。
  - **Bullshark / Tusk**：在 Narwhal 的 DAG 上做**几乎零额外消息**的排序共识。
- 效果：吞吐量大幅提升（数万~十万+ TPS），被 Aptos、Sui 等采用，是当前的前沿方向。

> **一条演进主线**：PoW（安全但慢）→ PoS（省能）→ BFT（快速最终性但难扩展）→ HotStuff（线性通信）→ DAG / Narwhal（把数据传播和共识解耦以突破吞吐上限）。每一步都在「安全 / 去中心化 / 性能」上换角度突破。

---

## 本篇小结

- 共识要同时保证 Safety 和 Liveness，而 FLP 定理说明异步下二者不可兼得，所以都要取舍。
- PoW 安全来自「作恶不划算」，代价是能耗和低 TPS；PoS 用质押 + Slashing 替代算力，解决了 Nothing-at-Stake。
- BFT 系（PBFT/HotStuff/Tendermint）提供确定性最终性；PBFT 的 3f+1 与 O(n²) 通信是关键，HotStuff 把通信降到 O(n)。
- DAG 与 Narwhal 的思路是「并行产块 / Mempool 与共识解耦」，用来突破吞吐上限。
- 记住两类最终性的区别：概率最终性（PoW/PoS）vs 确定性最终性（BFT）。
