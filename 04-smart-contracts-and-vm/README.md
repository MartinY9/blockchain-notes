# 第四篇 智能合约与虚拟机

> 虚拟机决定了「链能运行什么、多快、多安全」。
> 理解 EVM → WASM → Move 的演进，就理解了区块链可编程性的发展方向。

---

## 4.1 Ethereum EVM

**EVM（Ethereum Virtual Machine）** 是一个**栈式虚拟机（Stack VM）**，是以太坊的执行引擎。

- **Stack VM**：没有寄存器，所有运算基于操作数栈（push/pop）。设计简单、易于在所有节点上**确定性**执行——这是共识的前提（每个节点跑同样字节码必须得到同样结果）。
- **Opcode（操作码）**：EVM 指令集，如 `ADD`、`SSTORE`（写存储）、`CALL`（调用合约）、`SHA3` 等。每个 opcode 有固定 Gas 成本。
- **存储模型**：合约有 storage（持久、贵）、memory（临时、便宜）、stack（最便宜）。`SSTORE` 极贵，正因为它改变全局状态、需所有节点持久化。
- **Solidity**：最主流的合约语言，编译成 EVM 字节码（另有 Vyper 等）。
- **确定性要求**：EVM 禁止不确定操作（随机数、系统时间、浮点数），否则各节点结果不一致，共识就会破裂。

## 4.2 Gas 机制

### 为什么需要 Gas？

1. **防止无限循环 / 停机问题**：图灵完备的合约可能死循环。Gas 让每步执行都收费，Gas 耗尽即回滚——用经济手段绕开「停机问题」。
2. **为计算资源定价**：不同操作消耗不同资源（`SSTORE` 远贵于 `ADD`），Gas 反映真实成本，防止 DoS（垃圾交易刷爆节点）。
3. **费用市场**：`Gas 费 = Gas 用量 × Gas 价格`。EIP-1559 引入 base fee（销毁）+ priority fee（给验证者），拥堵时自动调价。

> 一句话理解：Gas 本质是**「反 DoS + 资源定价」机制**。任何要在公开、无准入环境运行任意代码的系统，都必须有类似的资源计量。

## 4.3 新一代虚拟机

### WASM（WebAssembly）

代表：**Polkadot（含 ink!）、CosmWasm、近年多条链**。

- **优势**：**跨语言**（Rust/C/C++/Go 等都能编译成 WASM）、执行效率高、有成熟的工业级工具链、生态大。
- 相比 EVM：性能更好、语言选择更多；但需要额外处理**确定性**（禁用浮点/非确定特性）和 Gas 计量（对 WASM 指令插桩计费）。

### Move VM

代表：**Aptos、Sui**（源自 Facebook Libra/Diem 项目）。

- **核心特点：资源安全（Resource Safety）**。Move 把资产建模为**「资源（resource）」** 类型，语言层面强制：
  - 资源**不能被复制**（no copy）——防止凭空造币。
  - 资源**不能被丢弃/凭空销毁**（no drop）——防止资产意外丢失。
  - 资源**只能被移动（move）**——所有权明确转移。
- 这从**语言类型系统层面**杜绝了很多 Solidity 里靠人肉小心才能避免的漏洞（如重入、余额算错）。
- 配合 **Object 模型**（见第二篇），Move 还能实现**并行执行**（无冲突对象并行）。

### 三代 VM 对比

| VM | 代表 | 语言 | 核心卖点 | 主要短板 |
|----|------|------|----------|----------|
| EVM | Ethereum | Solidity | 生态最大、事实标准 | 栈式、慢、难并行、安全靠人 |
| WASM | Polkadot/Cosmos | Rust 等多语言 | 跨语言、高性能 | 确定性/Gas 需额外处理 |
| Move VM | Aptos/Sui | Move | 资源安全 + 可并行 | 生态新、迁移成本 |

> **演进逻辑**：EVM 证明了「链上可编程」可行；WASM 追求「性能与语言自由」；Move 追求「从语言层面保证资产安全 + 并行」。方向是**更安全、更快、更易用**。

---

## 本篇小结

- EVM 是栈式虚拟机，强调确定性执行（禁随机/时间/浮点），保证各节点结果一致。
- Gas 的本质是「反 DoS + 资源定价 + 绕开停机问题」；EIP-1559 把手续费改成 base fee 销毁 + priority fee。
- WASM 的卖点是跨语言与高性能；Move 的卖点是从类型系统层面保证资源安全，并天然支持并行。
- 虚拟机演进方向：更安全、更快、更易用。
